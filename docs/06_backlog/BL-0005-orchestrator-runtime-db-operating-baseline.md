# BL-0005: Orchestrator Runtime DB 실제 운영 기준 확립 및 이관

- **상태**: 진행 중 (In Progress)
- **우선순위**: P1
- **등록일**: 2026-09-22 (KST)
- **관련 문서**: [Orchestrator Runtime DB 운영 기준](../01_governance/orchestrator-runtime-db-operations.md)

## 설명
Orchestrator의 상태와 기록을 관리하는 Runtime SQLite DB를 안정적으로 운영하기 위한 실제 설정 및 이관 작업을 수행한다. 현재는 `ORCHESTRATOR_JULES_STATE_DIR`를 이용해 **Jules 전용 상태 저장소 팩토리(`get_jules_state_repository`)가 준비**되었고, 이를 `execute_review_handoff`에 `jules_state_repository_factory` 인자로 주입할 수 있도록 통합 지점까지 구현 완료된 상태이다.
현재, 외부 상태 디렉터리 생성 및 빈 초기 SQLite DB 초기화가 완료되었으며, 실행 계정(`ubuntu:ubuntu`)의 최소 권한 적용까지 완료되었다. 하지만, 실제 1:1:1 결속 데이터는 미기록 상태로 남아 있으며, 백업·복구(RPO/RTO 포함) 체계는 미구성·미결 상태이다.

본 백로그는 향후 백업 및 복구 체계를 확립하고, 실제 1:1:1 결속 데이터를 정상적으로 기록 활성화하는 것을 최종 목표로 한다.

## 사용자 결정 필요 사항
실행 계정은 `ubuntu:ubuntu`로 권한 적용 완료되었으며, 빈 초기 DB 초기화도 완료되었다. 실제 운영 환경 적용(결속 데이터 쓰기 활성화)은 이후 단계로 진행할 예정이다.
백업 및 복구는 현재 미구성 상태이며, 이 작업을 진행하기 전에 아래 백업 및 복구 관련 사항들에 대한 추가 승인과 결정이 필요하다:

1. **백업 정책 (Backup Policy)**
   - 백업 실행 주기 (예: 매일 오전 3시, 매시간 등)
   - 백업 데이터의 보존 기간 (예: 30일 보관, 1년 보관 등)
2. **복구 목표 (Recovery Objectives)**
   - **RPO (Recovery Point Objective)**: 허용 가능한 최대 데이터 손실 시간.
   - **RTO (Recovery Time Objective)**: 장애 발생 시 복구까지 허용되는 최대 시간.

## 제약 및 통제 사항
- 모든 시스템 변경(백업 스케줄러 등록 등)은 기록되어 검토되어야 한다.
- 보안 원칙에 따라, 어떠한 설정이나 로그, 문서, PR에도 API 키, 토큰, Source Resource Name, 원시 프롬프트, 원시 활동/로그, 실제 경로 및 DB 내용이 포함되어서는 안 된다.

## 목표
사용자 결정이 완료되면, 해당 내용을 바탕으로 인프라 프로비저닝 또는 구성 스크립트를 작성하여 백업/복구 스케줄러 등록을 완수하고, 실제 1:1:1 결속 데이터를 기록 활성화한다.
