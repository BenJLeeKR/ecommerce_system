## 1. 작업 목적

로컬 개발 결과를 현재 서버의 테스트 환경에 안전하게 배포하고, 추후 운영 환경으로 같은 절차를 확장할 수 있는 기반을 만든다.

## 2. 범위

- `develop` 브랜치 기반 테스트 배포 흐름을 설계한다.
- 테스트 DB·비밀값·PG 샌드박스 키를 운영 환경과 분리한다.
- Docker 이미지 빌드, 배포, 상태 확인, 롤백 절차를 문서화한다.

## 3. 완료 조건

- 테스트 서버에 전용 환경 변수와 전용 DB를 사용한다.
- `develop` 변경을 검증 후 테스트 서버에 배포할 수 있다.
- 배포 실패 또는 장애 시 이전 버전으로 되돌리는 절차가 검증되어 있다.

## 4. 선행 조건과 위험 요소

- 실제 배포는 프로젝트 골격과 서버 접근·비밀값 관리 방식이 확정된 뒤 진행한다.
- 결제는 테스트 서버에서 PG 샌드박스만 사용하며 운영 키를 저장하지 않는다.
- 주문·결제·재고 변경은 기능 플래그와 롤백 계획을 별도 검토해야 한다.
