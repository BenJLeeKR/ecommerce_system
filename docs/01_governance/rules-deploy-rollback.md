# 배포 및 롤백 원칙

> 이 문서는 테스트계·운영계 배포를 준비하거나 실행하는 작업을 할 때 참조한다.

## 환경과 승인 경계

- 개발 작업 경로, 현재 테스트 서버, 향후 운영 서버는 서로 다른 환경으로 취급한다.
- 테스트계와 운영계는 DB·환경 변수·비밀값·PG 키를 분리한다. 운영 비밀값과 실제 PG 키는 Jules에 제공하지 않는다.
- 테스트계 배포, 운영계 승격, 롤백은 모두 사용자의 명시적 승인이 필요하다. `main` 병합만으로 자동 배포하지 않는다.

## 테스트계 배포

- 테스트계에는 사용자 승인으로 병합된 `main`의 특정 커밋 SHA 또는 그 커밋에서 빌드한 이미지 digest만 배포한다.
- 배포 기록에는 커밋 SHA, 이미지 digest, 배포 시각, 실행한 스모크 테스트와 결과를 남긴다.
- 테스트계는 사용자 검수와 통합 검증용이며, 운영 데이터·운영 PG 키를 사용하지 않는다.

## 운영계 승격과 릴리스 태그

- 운영 배포 전 테스트계에서 동일 커밋 또는 동일 이미지 digest를 검증한다.
- 사용자가 운영 승격을 승인하면 검증한 `main` 커밋에 릴리스 태그를 생성한다.
- 운영계는 `main`을 직접 추적하거나 새로 빌드하지 않고, 릴리스 태그가 가리키는 동일 이미지 digest만 배포한다.
- 운영계는 별도 서버·별도 DB·별도 비밀값을 사용한다.

## 롤백

- 모든 배포 단위는 이전에 검증된 릴리스 태그와 이미지 digest를 롤백 대상으로 사전에 명시한다.
- 문제가 발생하면 이전 태그의 동일 이미지로 되돌리고, 배포 후 스모크 테스트를 다시 실행한다.
- DB 마이그레이션이 포함되면 사전 승인된 복구 절차와 데이터 영향 검토를 함께 기록한다.
- 결제/주문/재고처럼 금전적 손실로 이어질 수 있는 영역은 가능하면 기능 플래그로 즉시 비활성화할 수 있게 설계한다.

## 배포 전 체크리스트

- [ ] 사용자 배포 또는 운영 승격 승인
- [ ] 대상 커밋 SHA와 이미지 digest 확인
- [ ] 테스트계 검증 및 비전문가 검수 완료
- [ ] 테스트계·운영계 DB, 비밀값, PG 키 분리 확인
- [ ] 롤백 대상 태그·이미지와 DB 복구 절차 명시
- [ ] 민감 영역 변경 시 기능 플래그와 모니터링·알림 대상 확인
