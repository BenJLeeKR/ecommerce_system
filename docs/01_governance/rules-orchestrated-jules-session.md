# 수동 Jules 실행 절차 (Manual Jules Execution Protocol) v0.1

> 상태: Draft — 루트 AGENTS.md와 CLAUDE.md의 절대 규칙을 보완하는 수동 폴백 절차입니다.

> **주의**: 이 문서는 자동화 기능을 사용할 수 없을 때 사용자 승인과 별도 Task Contract에 따라 제한적으로 적용하는 수동 폴백 절차입니다.

이 문서는 Codex-Jules Thin Orchestrator의 초기 운영 방식인 수동 복사-붙여넣기 절차를 정의합니다. 현재는 **LOW 위험 문서 작업**만을 대상으로 하며, 자동화로 전환되기 전까지 안전하고 통제된 방식으로 Jules를 실행하기 위한 기준을 제공합니다.

## 기본 원칙

- **대상 제한**: 오직 LOW 위험 문서 작업에만 이 절차를 적용합니다.
- **예외 대상**: 주문, 결제, 재고, 인증, 권한, DB 마이그레이션, 운영 인프라 관련 작업은 **현재 수동 실행 절차의 적용 대상이 아닙니다.**
- **사용자 승인 필수**: 사용자의 명시적인 승인이 있기 전에는 절대로 Jules 실행을 시작해서는 안 됩니다.
- **자동화 금지**: 자동 재시도, 자동 재작업, 자동 병합을 수행하지 않습니다. API 오류, 시간 초과, 중복 요청, 범위 위반 등 어떠한 문제라도 발생하면 즉시 상태를 `NEEDS_HUMAN_REVIEW`로 전환하고 사람의 개입을 기다립니다.
- **절대 규칙 (세션·브랜치·PR 1:1:1 바인딩)**:
  - Jules 플랫폼의 세션 1개 ↔ 브랜치 1개 ↔ PR 1개 강제 제약을 전제로 하며, 현재 작업의 식별자가 일관되게 연결되었는지를 최우선으로 확인합니다.
  - 이전 작업의 병합 또는 종료 후 시작하는 후속 작업은 반드시 새 Task Contract, 새 사용자 승인, 새 Jules 세션 ID를 사용하여 진행해야 합니다.

## 실행 절차 (수동 워크플로우)

### 1단계: Task Contract 작성 및 승인 (Codex & 사람)
1. Contract 작성 전에 대상 저장소에 적용할 **Project Profile의 ID와 버전**을 확인하고 이를 Contract에 기록합니다. (해당 Profile은 작업 범위를 자동으로 확장하지 않으며, 구체적인 경계는 Contract에 명시해야 합니다.)
2. Codex가 요구사항을 바탕으로 `docs/07_templates/task-contract-template.md` 템플릿에 맞추어 프롬프트 초안(DRAFT)을 작성합니다.
3. 사용자가 Contract 내용을 검토하고 승인(APPROVED)합니다.
4. 승인 증적 식별자와 타임스탬프(UTC/KST)를 Contract에 기록합니다.

### 계획 검토 횟수 제한 및 PR 기반 최종 검토
- **수정 요청 횟수 제한**: 일반적인 계획 명확화 목적의 Codex 수정 요청은 작업당 최대 3회로 제한합니다.
- **반복 수정 중단**: 3회 보완 후에는 계획 단계의 추가 반복 수정을 중단하고, 잔여 확인 사항을 요약합니다.
- **명시적 승인 필수**: 3회 초과가 자동 승인을 의미하지 않으며, 작성 단계(코드 작성 및 PR 제출)로 진행하기 위해서는 반드시 **사용자의 명시적 승인**이 필요합니다.
- **PR 기반 최종 검토**: 사용자가 승인한 경우에만 Jules가 작업을 수행하며, 작업 완료 후 Codex는 실제 PR diff를 기준으로 최종 검토와 수정 요청, 병합 가능 여부에 대한 검토 결과를 사용자에게 보고한다. PR 병합 여부의 최종 결정과 승인은 사용자가 한다.
- **예외 사항 (즉시 중단 및 `NEEDS_HUMAN_REVIEW` 전환)**:
  - 민감 영역 접근, 비밀값 노출, 허용 경로 위반, 자동 병합·자동 배포·`main` 병합 위반, 세션·승인 경계 위반 사항이 발생한 경우에는 횟수 제한 대상에서 제외됩니다.
  - 위와 같은 예외 상황 발생 시, 추가 계획 보완이나 작성 단계 진행 없이 즉시 중단하고 상태를 `NEEDS_HUMAN_REVIEW`로 전환합니다.

### 2단계: 프롬프트 전달 및 Jules 실행 (사람 & Jules)
1. 사용자는 승인된 Task Contract 기반의 프롬프트를 복사하여 Jules 에이전트 인터페이스에 수동으로 붙여넣기(Copy&Paste) 합니다.
2. Jules는 전달받은 프롬프트를 바탕으로 작업 브랜치와 PR을 생성하는 등의 작업을 수행합니다.

### 3단계: 결과 수집 및 검증 (Codex & 사람)
1. Jules의 작업이 완료되거나 중단된 후, 아래의 **Jules 결과 수집 체크리스트**를 통해 사람이 직접 결과를 수집하고 기록합니다. 최종 검토는 실제 PR diff를 기준으로 수행합니다.
2. 검증 결과 이상이 있거나, 허용된 경로를 벗어난 경우 즉시 작업을 중단하고 사람의 검토(`NEEDS_HUMAN_REVIEW`)를 받습니다.
