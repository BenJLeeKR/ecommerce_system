# 역할과 책임 (R&R) / 단계별 산출물

> 적용 원칙: Codex는 작업 지시의 구체화와 결과의 독립 검토를 담당하고, Claude Code는 승인된 범위 안에서 변경·테스트·PR 작성을 실행한다. 두 AI의 검토는 사용자의 승인·실제 검수·병합 결정을 대체하지 않는다.

## 단계별 산출물 및 승인 주체

| 단계 | 산출물 | 주관 담당 | 검토·승인 주체 |
|---|---|---|---|
| 1. 문서 (기획) | 요구사항 정의서 / 유저 스토리 / 우선순위 | 기획자(사용자) | 사용자 |
| 2. 분석·계획 | 분석 결과, 대안 비교, 작업 계획, Claude Code 실행 프롬프트 | Codex | 설계 승인자(사용자) |
| 3. 설계 | 기술 설계서(구조, API, DB 스키마 변경안, 영향 범위) | Claude Code | Codex 검토 후 설계 승인자(사용자) |
| 4. 이슈·작업 단위 | 범위, 수정 가능 파일, Definition of Done, 검증 방법 | Codex | 사용자 |
| 5. 구현 PR | 이슈 1개당 PR 1개, 변경 파일·이유·테스트 결과·검수 가이드 | Claude Code | Codex 검토 후 사용자 |
| 6. 테스트 | 단위/통합/시나리오 테스트 결과 리포트 | Claude Code | Codex 결과 검토 후 사용자 |
| 7. 검수·병합 | 비전문가 검수 결과, 병합·배포 판단 | 사용자 | 최종 의사결정자(사용자) |

## 역할

| 역할 | 담당 | 책임 |
|---|---|---|
| 기획자 | 사용자 | 요구사항 정의, 우선순위 결정, 범위 확정 |
| 설계 승인자 | 사용자 | 분석·계획·기술 설계의 승인/반려 |
| 작업 설계·검토 | Codex | 작업을 리뷰 가능한 단위로 분해하고, Claude Code용 프롬프트·완료 기준·검증 기준을 작성하며, 변경 결과의 설계 정합성과 규칙 준수 여부를 검토 |
| 실행 개발 | Claude Code | 승인된 프롬프트와 설계를 기준으로 문서·코드를 변경하고, 테스트·PR·검수 가이드를 작성 |
| 독립 결과 검토 | Codex | PR diff, 변경 범위, 문서 연결, 테스트 결과를 검토하고 보완 사항 또는 병합 가능 여부를 사용자에게 보고 |
| 검수자 | 사용자 | 검수 가이드에 따라 실제 동작을 확인 |
| 최종 의사결정자 | 사용자 | 병합·배포 여부, 범위 변경, 예외 승인 최종 결정 |

## Codex → Claude Code 인수인계 기준

Codex가 작성하는 실행 프롬프트에는 최소 다음을 포함한다.

1. 작업 목표와 제외 범위
2. 반드시 읽어야 하는 기준 문서와 대상 경로
3. 수정 가능 파일과 수정 금지 범위
4. 사용자가 승인해야 하는 미결정 사항과 에스컬레이션 조건
5. 완료 조건(Definition of Done)과 수행할 검증 방법
6. Worklog·인덱스·PR에 남길 기록

Claude Code는 범위를 넓히거나 설계 결정을 새로 내려야 하는 상황에서 임의 구현을 멈추고, 근거와 선택지를 사용자에게 보고한다.

## 결과 검토와 승인 경계

- Codex의 결과 검토는 구현 품질과 설계 정합성을 높이기 위한 독립 점검이다.
- Claude Code의 테스트 통과와 Codex의 검토 완료만으로 병합·배포가 자동 승인되지는 않는다.
- 민감 영역, DB 변경, 신규 외부 라이브러리, 범위 확대는 `CLAUDE.md`의 에스컬레이션 기준과 관련 거버넌스 규칙을 우선 적용한다.
- 설계·계획·결정·검증 결과는 대화에만 남기지 않고 문서 관리 규칙에 따른 프로젝트 문서에 기록한다.
