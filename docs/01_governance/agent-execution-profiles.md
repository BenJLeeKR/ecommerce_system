# 실행 에이전트 프로필 (Jules / Claude Code)

> 적용 범위: `roles.md`의 공통 R&R을 실행할 때 사용하는 도구별 환경·권한·결과물 차이. 공통 승인·민감 영역·품질 규칙은 모든 에이전트에 동일하게 적용한다.

## 공통 원칙

- Codex가 작성한 승인 범위 안에서만 작업한다.
- 한 작업·브랜치·PR에는 Jules 또는 Claude Code 중 하나만 실행 담당으로 지정한다.
- `main` 병합, 테스트계 배포, 운영계 승격은 사용자의 명시적 승인 없이는 수행하지 않는다.
- 비밀값을 저장소, 로그, 커밋 메시지, PR 설명에 남기지 않는다.

## Jules 프로필

| 항목 | 기준 |
|---|---|
| 작업 환경 | GitHub 저장소를 clone한 작업별 독립 VM |
| 허용 작업 | feature 브랜치, 커밋, PR, VM 내 설치·테스트·빌드 |
| 금지 범위 | SSH 서버 접속, 개발·테스트·운영 서버 경로 수정, 테스트/운영 DB 직접 접근, 운영 비밀값 사용 |
| 결과물 | GitHub PR, 변경 파일 목록, 실행한 검증과 결과, 미해결 사항 |
| 피드백 | Codex 검토 결과를 수정 프롬프트로 받아 같은 PR에 반영 |

Jules 작업 브랜치는 병합 전 개발·테스트 경로에 동기화하지 않는다. 사용자 승인으로 병합된 커밋만 Codex 또는 승인된 배포 절차가 안정 기준 경로와 테스트 서버에 반영한다.

## Claude Code 프로필

| 항목 | 기준 |
|---|---|
| 작업 환경 | 지정된 개발 작업 경로와 해당 feature 브랜치 또는 worktree |
| 허용 작업 | 로컬 코드 탐색, 문서·코드 변경, 테스트, GitHub PR 작성 |
| 금지 범위 | 테스트·운영 서버 경로 직접 수정, Jules가 담당한 동일 브랜치·PR 수정, 사용자 승인 없는 배포 |
| 결과물 | GitHub PR, 변경 파일 목록, 실행한 검증과 결과, 비전문가 검수 가이드 |
| 피드백 | Codex 검토 또는 사용자 피드백을 같은 PR에 반영 |

개발 작업 경로에 미커밋 변경이 있으면, 병합 후 안정 기준 동기화를 강제하지 않고 먼저 상태를 보고한다.

## 실행 에이전트 선택 기준

| 상황 | 기본 선택 |
|---|---|
| GitHub 기반의 독립적·범위가 명확한 문서/코드 작업 | Jules |
| 로컬 탐색·연속적인 복합 작업 또는 지정 개발 경로의 확인이 필요한 작업 | Claude Code |
| 민감 영역 | 도구와 무관하게 사전 설계·사용자 승인을 먼저 받고, 한 에이전트만 지정 |

선택 기준은 작업 지시의 첫 부분에 `실행 에이전트: Jules` 또는 `실행 에이전트: Claude Code`로 기록한다.
