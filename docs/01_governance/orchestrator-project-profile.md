# Project Profile: E-Commerce System (v0.1)

> 상태: Draft — 루트 AGENTS.md와 CLAUDE.md의 절대 규칙을 보완하는 Orchestrator 전용 Profile입니다.
**Profile ID:** `ECOMMERCE-SYSTEM-PROFILE-001`

## 1. 목적, 적용 범위 및 비대상
*   **목적:** E-Commerce 시스템(BenJLeeKR/ecommerce_system) 작업 시 적용할 공통 통제 경계, 보안 규칙 및 작업 원칙을 정의합니다.
*   **적용 범위:** Thin Orchestrator 저장소를 통해 관리 및 승인된 E-Commerce 시스템의 LOW 위험도 문서 작업. 향후 개별 Task Contract가 명시적으로 승인한 LOW 위험 문서 경로만 변경 가능합니다.
*   **비대상 (절대 변경 금지 영역):** 주문(Order), 결제(Payment), 재고(Inventory), 인증(Authn), 권한(Authz), DB 마이그레이션, 운영 인프라 관련 코드 및 설정은 자동 실행 대상에서 절대 제외됩니다. Orchestrator는 이커머스 애플리케이션 파일을 직접 수정하지 않으며, 실제 변경은 승인된 Task Contract와 Jules 작업 브랜치·PR을 통해서만 수행합니다.

## 2. 대상 저장소 식별자 및 기준 브랜치
*   **대상 저장소 식별자:** `BenJLeeKR/ecommerce_system` (식별 용도로만 사용)
*   **기준 브랜치:** `main` 브랜치는 기준 브랜치 및 기준 SHA 확인 대상으로만 사용됩니다.
*   **작업 브랜치:** 모든 실제 변경 작업은 `main`에 직접 커밋하지 않고, 승인된 Task Contract에 따라 별도의 작업 브랜치와 PR(Pull Request)에서만 수행됩니다.

## 3. Project Profile과 Task Contract의 관계
*   **Profile의 역할:** 프로젝트 전반에 적용되는 공통 통제 경계와 기본 원칙만을 정의합니다.
*   **Contract의 역할:** 개별 작업의 실제 허용/금지 경로, 기준 SHA, 위험도 분류 및 구체적 완료 조건은 반드시 개별 Task Contract에 명시됩니다.
*   **자동 확장 금지:** 본 Profile은 개별 Task Contract의 작업 범위를 자동으로 확장하지 않습니다. 정책이 상충할 경우, 항상 더 제한적이고 엄격한 규칙이 우선 적용됩니다.
*   **Orchestrator의 역할 한계:** Thin Orchestrator는 오직 Task Contract의 검증, Jules 세션 생성, 상태 추적, 결과 수집만을 담당합니다. 요구사항 분석, 아키텍처 결정, 작업 우선순위 판단, 혹은 PR 병합 여부를 결정하는 역할은 수행하지 않습니다.

## 4. 위험도 기준 및 허용 작업 범위
*   **초기 자동 실행 제한:** 초기 자동 실행은 오직 LOW 위험도로 분류된 단순 문서 작업만 허용됩니다. 그 외의 작업은 실행 전 엄격한 심사와 사용자 승인을 거쳐야 합니다.

## 5. 자동화 및 작업 통제 승인 경계
*   **금지 사항:**
    *   `main` 브랜치 자동 병합 절대 금지
    *   자동 배포 (테스트계, 운영계 포함) 금지
    *   실패 시 자동 재시도 및 자동 재작업 금지
*   **병합, 배포 및 승격 통제:** `main` 브랜치 병합, 테스트계 배포, 운영계 승격은 자동이든 수동이든 상관없이 사용자의 명시적인 승인 없이는 절대 수행하지 않습니다.
*   모든 실행 오류(API 오류, 타임아웃, 예외 발생 등) 시 즉시 작업을 중단하고 상태를 'NEEDS_HUMAN_REVIEW'로 전환하여 사용자의 명시적 승인을 대기합니다.

## 6. 보안 및 민감 정보 보호 원칙
*   **Git 및 문서 기록 금지:** API 키, 토큰, 비밀번호, SQLite 상태 DB 내용, 실행 로그 원본 등 어떠한 형태의 민감 정보도 Git 저장소(PR 포함)나 문서에 절대 기록하지 않습니다. 필요 시 가상의 식별자(예: `[repository-identifier]`)를 사용합니다.

## 7. 시간대(Timezone) 정책
*   시스템의 상태 정보 및 로그 기록 시 저장은 UTC를 기준으로 수행하되, **모든 문서(Worklog 등) 내 표기는 한국 표준시(KST)를 기준**으로 명시합니다.

## 8. 플랫폼 제약 및 세션/후속 작업 관리
*   **플랫폼 제약:** Jules 플랫폼의 **'세션 1개 ↔ 브랜치 1개 ↔ PR 1개'** 강제 제약을 전제로 모든 작업을 수행합니다.
*   **후속 작업 요건:** PR 병합 완료 또는 세션 종료 후 이어지는 모든 후속 작업은 이전 세션을 재사용할 수 없으며, 반드시 **새로운 Task Contract, 새로운 사용자의 명시적 승인, 그리고 새로운 Jules 세션**으로 진행해야 합니다.

## 9. 검증 체크리스트 및 롤백 방안
*   **검증:**
    *   문서 내 모든 Markdown 링크 무결성 확인
    *   커밋 전 `git diff --check`를 실행하여 포맷팅 및 구조적 오류 점검
*   **롤백 방안:**
    *   병합된 변경 사항에 문제가 발생한 경우, `git revert <커밋 SHA>` 명령어를 사용하거나 새로운 복구 PR을 생성하여 되돌립니다.
    *   미병합 PR의 경우, 사용자의 판단에 따라 즉시 Close 할 수 있으며, 브랜치 정리는 병합 또는 작업 종료 후 별도 확인 절차를 거쳐 수행됩니다.
