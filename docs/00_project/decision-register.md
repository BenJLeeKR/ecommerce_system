## 1. 개요 및 목적
본 문서는 프로젝트 진행 과정에서 의사결정권자(사용자)의 승인을 거쳐 확정된 **승인 완료 결정 사항**과, 향후 의사결정이 필요한 **미결(사용자 결정 대기) 항목**을 단일 문서에서 명확히 분리하여 추적·관리하기 위한 결정 레지스터(Decision Register) 초안이다.

본 문서는 `AN-0006` 및 `AN-0007` 분석 문서의 결과를 바탕으로 작성되었으며, 임의의 신규 정책 수립이나 미결 항목의 승인 확정 전환 없이 기존 승인 상태만을 보존한다.

## 2. 승인 완료 결정 레지스터

### 2.1. 핵심 기술 스택 및 DB 기본 규정

| ID | 결정 항목 | 확정 내용 및 정책 | 승인 근거 문서 |
|---|---|---|---|
| DEC-001 | 기술 스택 | Next.js (Frontend), NestJS + Prisma (Backend), TypeScript, PostgreSQL | `WL-0014`, `AN-0007` |
| DEC-002 | DB 테이블 명명 규칙 | 접두어 없는 복수형 소문자 뱀표기법 (`plural snake_case`, 예: `users`, `orders`, `inventory`) | `WL-0014`, `AN-0007` |
| DEC-003 | DB 계정 및 접근 | 공용 PostgreSQL 인스턴스 내 프로젝트 전용 DB 구축 및 전용 최소 권한 계정 사용 | `WL-0014`, `AN-0007` |

### 2.2. 민감 도메인 핵심 정책 (8건)

| ID | 결정 항목 | 확정 내용 및 정책 | 승인 근거 문서 |
|---|---|---|---|
| DEC-004 | 재고 예약 TTL | 15분 (`Asia/Seoul` 기준, UTC로 DB 저장) | `AN-0006`, `WL-0019` |
| DEC-005 | 재고 동시성 제어 | 조건부 원자 갱신 (`UPDATE inventory SET quantity = quantity - X WHERE quantity >= X`) | `AN-0006`, `WL-0019` |
| DEC-006 | 트랜잭션 경계 | PG 결제 호출은 DB 트랜잭션 외부 수행. [주문 생성 + 재고 예약] 1개 트랜잭션, [PG 콜백 처리 + 결제 상태 갱신 + 재고 확정] 1개 트랜잭션 분리 | `AN-0006`, `WL-0019` |
| DEC-007 | 재고 만료 스케줄러 | 1분 주기 실행 | `AN-0006`, `WL-0019` |
| DEC-008 | 결제 PG 멱등성 | 결제 시도별 고유 멱등키(`idempotency_key`) + 상태전이 조건(`REQUESTED`) 결합 복합 정책 | `AN-0006`, `WL-0019` |
| DEC-009 | PG 거래 ID 제약 | `pg_transaction_id`에 Unique 제약 부여 | `AN-0006`, `WL-0019` |
| DEC-010 | 결제 이상 콜백 처리 | 지연/역순 등 예외 콜백 수신 시 모니터링 알림(민감정보 제외) 후 운영팀 수동 대사 처리 연계 | `AN-0006`, `WL-0019` |
| DEC-011 | 결제 반복 실패 제한 | 동일 주문 결제 실패 3회 누적 시 재결제 차단 및 재고 복구 | `AN-0006`, `WL-0019` |

## 3. 미결 (사용자 결정 대기) 레지스터

아래 항목들은 사용자 승인이 완료되지 않은 미결 상태이며, 임의로 결정하거나 반영하지 않고 현 상태를 보존한다.

| ID | 분류 | 미결 항목 명칭 | 현재 상태 및 관리 방침 |
|---|---|---|---|
| PEND-001 | DB 설계 | Primary Key 채택 방식 (UUID vs BigInt Auto-increment) | 사용자 미결정 상태 보존 |
| PEND-002 | DB 설계 | Enum 데이터 타입 처리 방식 (DB Enum vs String/Varchar) | 사용자 미결정 상태 보존 |
| PEND-003 | 인증/보안 | 토큰 만료 시간 및 로그인 실패 잠금 임계값 | 사용자 미결정 상태 보존 |
| PEND-004 | 인증/보안 | API Rate Limiting 및 비밀번호 재설정 횟수 제한 | 사용자 미결정 상태 보존 |
| PEND-005 | 도메인/기획 | 카테고리 삭제 시 소속 상품 처리 방안 | 사용자 미결정 상태 보존 |
| PEND-006 | 도메인/기획 | 회원 탈퇴 시 진행 중 주문 제한 규칙 | 사용자 미결정 상태 보존 |
| PEND-007 | 도메인/기획 | 회원당 기본 배송지 Unique 처리 방식 | 사용자 미결정 상태 보존 |
| PEND-008 | 화면/UX | 장바구니 품절 상품 처리 UX 및 대시보드 통계 기준 | 사용자 미결정 상태 보존 |
| PEND-009 | 화면/UX | 관리자 재고 조정 입력 방식 (증감 vs 절대값) | 사용자 미결정 상태 보존 |
| PEND-010 | 화면/UX | 비밀번호 재설정 모달 또는 별도 화면 분리 여부 | 사용자 미결정 상태 보존 (`AN-0005` 기준) |
| PEND-011 | 화면/UX | 관리자 회원 상세 화면 신설 여부 | 사용자 미결정 상태 보존 (`AN-0005` 기준) |
| PEND-012 | 화면/UX | 결제 결과 화면의 폴링 방식 | 사용자 미결정 상태 보존 (`AN-0005` 기준) |

## 4. 향후 관리 및 정합화 계획
1. **문서 상태 관리**: 결정 레지스터 문서 상태는 `Draft`로 시작하며, 이번 작업 범위에서는 문서 상태를 변경하지 않는다.
2. **미결 사항 승인 시 반영 절차**: 향후 미결 사항(`PEND-001`~`PEND-012`)에 대해 사용자의 결정이 완료되면, `AN-0007`에서 제시된 후속 PR 분할안(DB/도메인, 인증/보안, 화면/UX)에 따라 변경 범위를 최소화하여 순차적으로 정합화를 진행한다.
