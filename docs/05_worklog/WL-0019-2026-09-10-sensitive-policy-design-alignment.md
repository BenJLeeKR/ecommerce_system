## 1. 목적
사용자가 승인 완료한 8건의 민감 도메인(재고, 결제, 트랜잭션 등) 정책과 초기 인프라 백업/복구 기준을 기존 아키텍처, 도메인 모델, API 설계, 데이터베이스 설계, 화면 명세 등 전체 설계 문서 및 분석/계획 문서에 정합화하여 일관성을 확보함.

## 2. 수행 내용
- **재고 정책 반영**: 재고 예약 TTL을 15분으로 명시, `Asia/Seoul` 기준 1분 단위 스케줄러 실행 명시, 동시성 제어를 위해 조건부 원자 갱신을 사용하도록 도메인 모델과 데이터베이스 설계에 반영.
- **트랜잭션 설계 구체화**: 주문 생성과 재고 예약을 1개 트랜잭션으로, PG 결제 호출을 트랜잭션 밖으로 분리, 호출 완료 후 결제 상태 갱신과 재고 차감 확정을 1개 트랜잭션으로 처리하도록 수정.
- **결제 멱등성 및 예외 처리 정책 반영**: 결제 시도별 고유 멱등키와 상태 전이를 결합한 복합 정책 명시, 역순·불일치 콜백 발생 시 단순 무시하지 않고 민감정보를 제외한 모니터링 알림 후 운영팀 수동 대사 처리로 연계. `pg_transaction_id`에 Unique 제약 추가.
- **결제 반복 실패 정책 반영**: 동일 주문 결제 실패 3회 제한, 3회 누적 시 추가 결제 차단 및 재고 복구 중복 수행 방지 처리, 화면에도 3회 누적 시 안내 메시지와 버튼 미노출 처리(서버 차단 검수 포인트 추가) 반영.
- **초기 인프라 정책 반영**: 공용 PostgreSQL 내 프로젝트 전용 DB 구축 및 최소 권한 사용, 매일 KST 03:00 백업(일간 31개, 월간 12개 보존), 목표 RPO 24시간/RTO 4시간 명시. 운영 담당자 책임하에 전용 DB 생성 후 1회, 운영계 승격 전 복구 테스트 재검증 수행 명시.

## 3. 판단 및 결정
- 민감 영역 정책 옵션들에 대해 사용자 승인이 완료되었으므로, 기존 문서의 "사용자 결정 대기" 상태를 "사용자 승인 완료"로 갱신함.
- `PL-0008` 문서 전체 상태는 유지하되 7장 선결 조건만을 승인 완료로 갱신함.
- 화면 명세는 클라이언트 단의 제한이 1차 UX 방어일 뿐이라는 점을 검수 포인트로 명확히 함.
- 코드 및 DB 마이그레이션 변경 없이, 설계 문서 갱신 작업으로만 한정하여 수행함.
