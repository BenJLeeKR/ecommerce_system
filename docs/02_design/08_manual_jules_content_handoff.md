# 수동 Jules 콘텐츠 인계 설계 (Manual Jules Content Handoff)

## 개요
이 문서는 Orchestrator 시스템 내에서 Codex 검토 소비자를 위해 Jules 세션의 생성 원문 활동(콘텐츠)을 일회성 수동 조회 방식으로 전달하는 진입점의 설계를 정의합니다. 이 진입점은 자동화된 상태 전이나 승인 프로세스와 철저히 분리되며, 비영속성, 비로그성, 최소 권한 원칙을 엄격하게 준수합니다.

## 목표
- Jules 세션 활동 중 수동 검토에 필요한 명시적 허용 유형의 원문 콘텐츠만 추출하여 메모리 상에서 안전하게 전달합니다.
- `userMessaged` 프롬프트, 자격 증명, Source Resource Name 등 민감 메타데이터 노출을 원천 차단합니다.
- API 호출 전 Contract, 승인 증적, 세션 바인딩 정보를 엄격히 검증하여 무단 조회를 방지합니다.

## 허용 유형 및 단일 필드 추출 정책
원문 조회 시에는 다음 유형의 활동 중 해당하는 단일 필드 내용만 추출하며, 다른 메타데이터나 구조는 폐기합니다.
1. `agentMessaged`: `message`
2. `planGenerated`: `plan` (내부 구조 포함)
3. `progressUpdated`: `message`
4. `sessionCompleted`: `summary`
5. `sessionFailed`: `failureReason`

`userMessaged`는 사용자 프롬프트 보호를 위해 완전히 제외됩니다.

## 비영속 및 비로그 경계
- **조회 객체 마스킹**: 반환되는 조회 결과 객체는 `__repr__`, `__str__`, `to_dict` 메서드를 오버라이드하여, 로깅이나 직렬화 시 원문이 `<REDACTED>`로 처리되도록 합니다.
- **기록 차단**: 조회된 원문은 Git, 문서, Pull Request, SQLite DB, 파일 시스템, 콘솔/서버 로그에 어떠한 형태로도 기록되지 않아야 합니다.

## 검증 및 오류 처리
- **API 사전 검증**: Contract 해시, 승인 증적 상태(`ACTIVE`), 세션 ID 불일치를 API 호출 전에 검사합니다.
- **Fail-Safe 차단**: 알 수 없는 활동 유형, 예상치 못한 필드 구조, 시간 정렬 신뢰성 오류, JSON/시간 파싱 오류 발생 시, 원문 추출을 즉시 중단하고 어떠한 데이터 노출 없이 `NEEDS_HUMAN_REVIEW` 상태를 반환합니다.

## 제약 사항
- 이 진입점은 자동 승인, 자동 검토, 자동 병합, 자동 배포, 자동 재시도, 자동 재작업 절차를 포함하지 않습니다.
- 1:1:1 바인딩(Session:Branch:PR)은 사전 검증에 사용될 수 있지만, 본 진입점 호출로 인해 상태 전이나 영구 바인딩 데이터가 변경되지 않습니다.
