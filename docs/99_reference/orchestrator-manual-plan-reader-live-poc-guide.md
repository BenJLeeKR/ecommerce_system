# Orchestrator 수동 Plan 조회 Live POC 절차 가이드

본 문서는 Task Contract에 명시된 범위 내에서 수동 Plan 검토 조회를 위한 Live POC(Proof of Concept)의 성공 절차, 검증 경계, 그리고 제한 사항을 정의합니다. 시스템 보안 및 데이터 보호 정책에 따라 원문 Plan, 세션 식별자, 활동 및 로그 정보, API 호출 세부사항, 환경 변수 정보, SQLite 데이터, 그리고 실제 런타임 경로는 문서에서 철저히 배제됩니다.

## 1. 개요 및 목적

이 문서의 목적은 수동 검토 대기 상태의 진행 중인 세션에 대하여, 자동화된 도구 개입 없이 수동으로 Plan 변경 사항을 조회하고 검증하기 위한 안전한 절차를 수립하는 것입니다.
해당 절차는 Live POC 환경에서 제한적으로 수행되며, 사전에 설정된 안전 경계와 제약 조건을 준수하는 범위 내에서만 동작합니다.

## 2. 비민감 성공 절차 (Non-Sensitive Execution Procedure)

수동 Plan 조회 기능이 올바르게 동작하는지 확인하기 위한 절차는 다음과 같습니다.

1. **사전 준비 상태 검증:** 대상 세션이 수동 검토가 필요한 상태(예: NEEDS_HUMAN_REVIEW)로 올바르게 전환되었음을 확인합니다.
2. **조회 명령 실행:** Orchestrator가 제공하는 수동 인터페이스(예: 진입점 스크립트 또는 어댑터)를 통해 대상 작업의 Plan을 조회합니다. 이 과정에서 직접적인 DB 쿼리나 API 호출 방식을 노출하지 않습니다.
3. **응답 데이터 추출:** 반환된 결과에서 원시 데이터(Raw Payload)가 아닌, 사전 정의된 형태의 객체 구조(예: Plan 단계의 제목과 설명)로 정제된 결과가 수신됨을 확인합니다.
4. **결과 확인:** 반환된 Plan 내용이 현재 세션의 작업 계획과 일치하는지 대조합니다. 이 단계에서 민감 데이터가 포함되어 있지 않은지 확인합니다.

## 3. 검증 경계 (Verification Boundaries)

Live POC의 무결성을 보장하기 위해 다음과 같은 검증 경계를 적용합니다.

- **결속 확인 유예:** 수동 검토 단계이므로, 해당 세션에 대한 단일 브랜치와 단일 PR의 생성 및 1:1:1 결속(Session:Branch:PR)은 이 단계에서 요구되거나 검증되지 않습니다.
- **비영속성 (Non-persistence):** 조회 과정에서 처리되는 Plan 내용은 메모리 상에만 존재해야 하며, 어떠한 형태의 로깅, 파일 쓰기, 혹은 데이터베이스 저장을 발생시켜서는 안 됩니다.
- **예외 처리:** 만약 조회 중 중복 데이터, 순서 모호성, 형식 오류, 또는 누락된 필드가 감지될 경우, 시스템은 에러의 상세 내역을 노출하지 않고 즉각 조회를 중단(Abort)해야 합니다.

## 4. 제한 사항 및 제외 범위 (Limitations & Out-of-Scope)

POC 수행 및 시스템 운영에 있어 다음 항목들은 본 절차의 범위에서 엄격히 제외됩니다.

- **자동화 작업 금지:** 자동 승인(Auto-approve), 자동 검토, 자동 병합, 자동 배포, 그리고 재시도 및 재작업 로직은 본 범위에 포함되지 않으며 실행되지 않습니다.
- **Live POC 재실행 불가:** 동일한 세션 또는 상태에 대한 Live POC의 반복적인 재실행은 지원하지 않습니다.
- **민감 정보 기록 금지:** 문서, 출력 화면, 디버깅 로그, Pull Request 내용 등에 원문 Plan 텍스트, 세션 식별자, 시스템 환경 정보, 데이터베이스 위치 등의 식별 가능한 민감 정보 기록을 금지합니다.
- **운영 DB 격리:** 본 POC는 프로덕션 운영 DB 또는 데이터에 영향을 주지 않도록 논리적으로 분리된 환경에서 실행됩니다.

## 5. 결론

본 문서는 수동 Plan 검토 과정을 안전하고 제한된 환경에서 검증하기 위한 최소한의 절차와 규칙을 규정합니다. 지정된 경계를 벗어나는 어떠한 행위나 자동화는 엄격히 금지되며, 오직 정합성 확인 용도로만 수행되어야 합니다.
