# Orchestrator 수동 계획 검토 조회기 설계

## 1. 개요
에이전트가 세션의 최신 계획 원문을 정확히 일회 조회하여 검토하기 위한 단회성 수동 진입점의 설계 원칙입니다.

## 2. 주요 책임 및 제약 사항
- **조회 전용 및 자동화 배제**: 수동 계획 검토 조회 인터페이스로서, 어떠한 자동 승인, 자동 병합, 자동 배포 로직도 포함하지 않습니다.
- **단일 책임 보장**: 기존의 일반적인 활동 요약 조회 기능은 비민감 요약 상태용으로 유지되며, 계획 원문은 수동 계획 검토 전용의 좁은 조회 경계를 통해서만 획득됩니다.

## 3. 풀 리퀘스트 이전 단계 검증 및 결속 유예
- **최종 결속 유예**: 풀 리퀘스트 생성 이전 단계에서 호출되므로, 최종 세션과 브랜치 및 풀 리퀘스트 간의 일대일 결속 확인은 유예됩니다.
- **사전 검증 항목**:
  - 외부에서 주입된 세션 식별자와 실제 반환된 세션 식별자의 일치 및 올바른 자원 포맷 검사
  - 생성 결과의 태스크 식별자와 계약 상의 태스크 식별자 일치 여부
  - 계약의 기준 커밋 해시 검증 (해시 무결성 검증과 사전 확인을 통해 보장됨)
  - 계약의 계획 승인 필수 여부가 참이고 자동 병합 설정이 거짓인지 확인
  - 승인 증적 상태 확인 및 해시 무결성 검증
- **오류 처리**: 위 조건 중 하나라도 충족하지 못하면 외부 시스템 조회 없이 즉시 사람 검토 대기 상태를 반환합니다.

## 4. 단일 계획 이벤트 키 확정 원칙
- **정확한 키 매핑**: 실제 구현 및 승인된 계약과 일치하게 API 응답의 `planGenerated.plan`은 반드시 객체 형식이여야 하며, 내부의 `steps` 배열을 통해서만 원문을 추출합니다. 다른 키의 추정 및 대체 탐색은 엄격히 금지됩니다.
- **엄격한 포맷 및 시간 검사**: `steps`가 존재하지 않거나 빈 배열인 경우, 배열 요소가 객체가 아니거나 `title`, `description`이 문자열이 아닌 경우, 기존 문자열형 구조를 포함해 예상 외 구조가 발견된 경우, 그리고 시간 순서를 신뢰할 수 없는 상황(중복 시각, 포맷 오류 등)이 발생하면, 원문 반환 없이 즉각 `NEEDS_HUMAN_REVIEW`로 처리하여 비정상적인 구현 추정을 원천 차단합니다.

## 5. 비영속 및 비로그 경계
- 계획 원문은 일회성 반환 객체에만 임시로 존재하며, 일회성 검토 용도로만 사용됩니다.
- 반환 객체의 문자열 변환이나 직렬화 메서드 호출 시 원문 텍스트는 접근 불가 문구로 마스킹 처리됩니다.
- 버전 관리 시스템, 풀 리퀘스트, 마크다운 문서, 데이터베이스, 예외 메시지, 콘솔 및 파일 로그 등 어떠한 영구 저장소나 로그에도 원문 데이터가 기록되거나 노출되지 않도록 설계 및 테스트됩니다.
