## 1. 분석 목적
Orchestrator의 상태와 실행 기록을 영속화하는 Runtime SQLite DB의 백업, 복구 방법, 그리고 RPO/RTO 기준에 대한 옵션을 분석한다. 이를 통해 운영 안정성을 확보하기 위한 기준을 마련하며, 본 문서는 설계 및 정책 결정을 목적으로 작성된다.

## 2. 전제 및 경계 (가드레일)
- **실제 반영 금지**: 본 분석은 권장안 제시가 목적이며, 실제 인프라 환경(백업/복구 스케줄러 등록, 권한 변경, 코드 수정, 실제 DB 경로 변경 등)에는 어떠한 변경도 가하지 않는다.
- **민감 정보 기록 금지**: 실제 백업/상태 저장소의 절대 경로, DB 파일명, API 키, 토큰, Source Resource Name, 원시 데이터 등은 문서 및 PR에 일절 기록하지 않는다.

## 3. 대안 비교 분석

### 3.1 백업 방식 옵션
- **옵션 A: SQLite Backup API (또는 `sqlite3 .backup` 명령)**
  - 장점: 실행 중인 DB와 함께 일관된 스냅샷을 생성할 수 있다.
  - 단점: 별도의 스크립트 작성 및 스케줄러 등록이 필요하다. 일관성을 보장하는 대신, 짧은 데이터베이스 잠금(Lock) 및 이에 따른 성능 영향 발생 가능성이 있으므로 실제 운영 전 검증이 필요하다.
  - 평가: SQLite 환경에서 일관성 확보를 위해 가장 권장되는 백업 방식.

- **옵션 B: 파일 복사 (File Copy)**
  - 장점: 단순하고 직관적임.
  - 단점: 복사 진행 중 DB 쓰기 발생 시 파일 손상 또는 불일치 가능성이 존재함.

### 3.2 주기 및 RPO/RTO 옵션
- **옵션 A (초기 인프라 권장 기준)**
  - RPO: 24시간 (일 1회 백업)
  - RTO: 4시간
  - 장점: 구현이 단순하고 스토리지 비용이 낮아 MVP 단계에 적합.
- **옵션 B (강화 기준)**
  - RPO: 1시간 (매시간 백업)
  - 장점: 데이터 손실 최소화.
  - 단점: 백업 스크립트 실행 빈도 증가, 스토리지 사용량 증가.

## 4. 복구 분석 및 절차 (설계 수준)
RTO(목표 복구 시간) 4시간을 준수하기 위해서는 복구 과정에서의 지연을 방지하기 위한 사전 설계와 연습이 필수적이다. 복구 절차는 다음과 같은 설계 원칙을 따른다:
1. **백업본 선택**: 목표 시점(RPO) 이내의 무결성이 보장된 최신 백업 파일을 식별.
2. **복원(Restore)**: 손상된 Runtime DB 파일을 백업본으로 안전하게 교체(필요 시 임시 서비스 차단).
3. **소유자 및 권한 재적용**: 복원된 파일이 어플리케이션 계정(예: `ubuntu`)에서 올바르게 읽기/쓰기가 가능하도록 최소 권한 기준(chown, chmod)을 정확히 재적용.
4. **검증**: `PRAGMA integrity_check` 등을 통해 SQLite 무결성을 검증하고, 상태 저장소 팩토리(Jules/Codex) 초기화가 정상적으로 이루어지는지 확인.

위의 절차가 RTO 4시간 내에 확실히 수행될 수 있도록, 향후 운영 체계에서 검증(Drill) 계획이 마련되어야 한다.

## 5. 결론 및 권장안 (Codex 권장안 / 사용자 승인 대기)
본 분석을 바탕으로 다음과 같은 초기 권장안을 제시한다.

- **백업 방식**: `sqlite3 .backup` 기반 스냅샷 수행 (잠금/성능 영향 사전 검증 포함)
- **백업 주기**: 일 1회
- **보존 기간**: 30일
- **RPO**: 24시간
- **RTO**: 4시간

위 사항은 사용자의 확정 없이는 실제 운영 값으로 적용되지 않으며, 사용자 결정 대기 상태이다.

## 6. 사용자 결정 및 후속 구현 항목
위 권장안이 승인될 경우 다음 항목들은 향후 인프라 구성 Task에서 결정되고 구현되어야 한다:
- **백업 저장 위치의 Git 분리**: 백업 파일이 Git 저장소에 포함되지 않도록 분리 구성.
- **엄격한 접근 통제**: 백업 저장소 및 복구 스크립트에 대한 최소 권한 부여 원칙 확립.
- **복원 연습(Drill) 필요성**: 실제 장애 발생 시 RTO 4시간 준수를 보장하기 위한 정기적인 복구 훈련 계획.
