## 1. 개요 및 목적
본 분석 문서는 `DECISION-ALIGNMENT-INVENTORY-001` 태스크에 따라 작성되었습니다.
목적은 프로젝트의 현재 사용자 승인/미결 결정 사항을 인벤토리화하고, 기존 기준 문서(`PROJECT_STATE.md`, 아키텍처 문서, 데이터베이스 설계 문서 등) 간의 동기화가 필요한(불일치) 항목을 식별하여, 이후 이를 정합화하기 위한 후속 PR 분할 방안을 제시하는 것입니다.
본 문서 작성 과정에서 기존 거버넌스 및 설계 문서 원본은 수정되지 않았으며, 순수하게 읽기 전용 탐색에 기반합니다.

## 2. 사용자 결정 사항 인벤토리 (Decision Inventory)

탐색 결과, 문서에 명시되어 있는 확정 및 승인 대기 정책은 다음과 같습니다.

### 2.1 승인 완료 정책 (Confirmed Policies)
*   **기술 스택**: Next.js + NestJS + PostgreSQL + Prisma 기반 모듈형 모놀리스
*   **리뷰 도메인 정책**: MVP 범위에서 완전 제외
*   **민감 도메인 8건 승인 완료 (AN-0006 반영 완료)**:
    1.  재고 예약 TTL 15분 (KST 기반 1분 단위 스케줄러)
    2.  재고 동시성 제어: 조건부 원자 갱신 (Optimistic-like)
    3.  트랜잭션 경계: PG 호출 분리 후 전/후 별도 트랜잭션
    4.  결제 멱등성 정책: 복합 멱등성 정책 (idempotency_key 및 상태 조건 갱신)
    5.  결제 반복 실패 정책: 3회 누적 시 완전 실패 및 차단
    6.  PG 거래 ID 유일성 제약: Unique 제약 추가 승인
    7.  역순·불일치 콜백 예외 정책: 모니터링 알림 후 수동 대사 처리
    8.  인프라 백업/복구 초기 기준: 자동 백업 일 1회(31일/12월 보존), RPO 24h, RTO 4h 승인
*   **기타 규칙**:
    *   한국어 작성 및 KST 시간 기준 사용
    *   테이블 명명 규칙: 복수형 snake_case, 접두어 없음

### 2.2 미결/승인 대기 정책 (Pending Approvals / Needs Confirmation)
*   데이터베이스 세부 스키마 및 데이터 타입(UUID, Enum, Prisma 매핑 등) 최종 정책 (현재 Codex 권장안 상태, PROJECT_STATE.md 명시)
*   카테고리 삭제 정책 (database-design.md의 ➕ 확인 필요 항목)
*   회원당 기본배송지 unique 처리 방식 (database-design.md의 ➕ 확인 필요 항목)
*   PREPARING 단계에서의 취소 허용 범위 및 처리 정책 (domain-model.md의 ➕ 확인 필요 항목)
*   로그인 실패 잠금 정책 등 보안 수치 (domain-model.md 10장)
*   초기 복구 인프라의 실제 복구 절차 수립 및 테스트 수행 (DB 생성 후 진행 필요 대기)
*   로컬/스테이징/테스트 환경 구체적 배포 절차 및 DB 최소 권한 접근 정보 확인 (PROJECT_STATE.md 선행 조건)

## 4. 후속 정합화 PR 분할안 제시

상기 식별된 불일치 항목들을 안전하게 정합화하기 위해, 한 번의 대형 PR보다는 아래와 같이 논리적으로 분할된 후속 PR(Task)을 진행하는 것을 제안합니다. (본 제안은 실행 계획일 뿐이며, 현재 문서에서는 텍스트로만 남깁니다.)

*   **후속 PR 1: 설계 문서 상태 플래그 및 체크리스트 정합화**
    *   **대상:** `architecture-overview.md`, `domain-model.md`, `database-design.md`
    *   **내용:** 기 확정된 민감 정책 및 초기 인프라 정책에 맞추어 각 문서 하단의 "승인 체크리스트" 상태(체크박스 [x])를 갱신합니다. 문서 전체가 Draft로 표기된 모순을 해결하고, 미결 항목(➕)을 제외한 나머지는 승인 완료(Approved) 상태임을 명시적으로 업데이트합니다.
*   **후속 PR 2: PROJECT_STATE.md 미결 사항 종합 동기화**
    *   **대상:** `PROJECT_STATE.md`
    *   **내용:** 도메인 모델과 데이터베이스 설계에 흩어져 있는 ➕ 확인 필요(Pending) 항목들(카테고리 삭제 정책, 회원 배송지 유일성, 취소 정책 등)을 수집하여 `PROJECT_STATE.md`의 '5. 미결 사항 및 확인 필요 사항' 섹션에 일괄 등재합니다. 이를 통해 전체 프로젝트 관점에서 미결 항목을 단일 위치에서 추적 가능하도록 합니다.
